
# Original Prompt and Results

# PR-1

## Purpose

Implement a simple simulated sauna temperature and relative humidity sensor for the legacy application. The sensor should simulate realistic sauna states and provide measurements through the required HTTP API endpoints. Unit tests are included to verify the sensor behavior and HTTP interface.

## Prompts

### Prompt 1

We are developing a legacy system for a university group project in Software Development, Maintenance and Operations.

My assigned component is a simulated sauna temperature and humidity sensor written in Python. There is no physical hardware, so the sensor must simulate realistic sauna readings.

The project leader has provided the following public API specification for the legacy application:

### Public HTTP API

The legacy application must host a simple web server with these public endpoints:

1. `GET /health`

   * Always return HTTP status `200`.
   * Return the plaintext response:
     `OK`
   * This endpoint is used to verify that the service is alive.

2. `GET /`

   * Return a JSON object containing the current temperature and relative humidity.

3. `GET /measurements`

   * Return the same type of JSON measurement as `/`.
   * The response should contain the current temperature and relative humidity.

Because this is a simulator, the measurement values may contain a degree of randomness, but they should still behave realistically.

### Sensor requirements

The sensor measures:

1. Temperature in degrees Celsius.
2. Relative humidity in percentage.

The sensor is not connected to real hardware. It must simulate realistic sauna readings.

Requirements:

* Use Python.
* Keep the implementation simple, readable, and easy for university group members to understand and review.
* Generate realistic temperature and relative-humidity values rather than completely unrelated random values.
* Values should change gradually between readings where appropriate.
* The simulation should support different sauna states such as:

  * cold/off
  * heating
  * hot sauna
  * cooling
* A temporary increase in relative humidity may occur during sauna use.
* Keep temperature and humidity within sensible physical ranges for the simulation.
* The sensor should produce a clear measurement containing temperature and relative humidity.
* The HTTP API must expose the sensor measurement through `/` and `/measurements`.
* The `/health` endpoint must return HTTP 200 with plaintext `OK`.
* Return measurements as JSON.
* Design the sensor and its public interface so that it can later be connected to a separate gateway component.
* Do not implement the gateway yet.
* Do not implement ML-KEM, encryption, or other advanced security features yet unless specifically required by the public API.
* Keep the design suitable for a simulated resource-constrained legacy device.
* Avoid unnecessary external dependencies.
* Prefer Python standard-library modules.
* Keep the sensor logic separate from the HTTP/API logic where practical, so the sensor can be tested independently.
* Make the code easy to test.
* Include unit tests for:

  * sensor creation
  * measurement structure
  * temperature range
  * humidity range
  * realistic state behavior
  * gradual changes where applicable
  * HTTP `/health` response
  * HTTP `/` measurement response
  * HTTP `/measurements` measurement response
* Do not over-engineer the solution.
* Keep the implementation appropriate for a university legacy-system modernization project.

### Important compatibility requirement

The public API described above is part of the existing legacy application's interface. Do not rename or remove the endpoints.

The required endpoints are exactly:

* `GET /health`
* `GET /`
* `GET /measurements`

The `/health` response must be:

* HTTP status: `200`
* Content: plaintext `OK`

The measurement endpoints must return JSON containing the current temperature and relative humidity.

### Before writing the code

First identify and briefly explain the assumptions you are making about:

* temperature ranges
* humidity ranges
* update/measurement behavior
* sauna states
* randomness and gradual changes
* JSON measurement format
* HTTP server implementation
* how the legacy API is kept simple

Then generate the complete implementation and unit tests.

Keep the code simple and easy to review. Do not add unnecessary frameworks, architecture, dependencies, or features that are not required by the specification.

After generating the code, briefly explain the design decisions and how the implementation satisfies the public API specification.

### Results 1

The LLM generated the `sensor.py` implementation and the `test_sensor.py` unit tests.

The implementation includes:

* Simulated temperature and relative humidity measurements.
* Cold, heating, hot, and cooling sauna states.
* Gradual changes between measurements.
* Random sensor variation.
* Sensible temperature and humidity limits.
* A simple HTTP interface with `/health`, `/`, and `/measurements`.
* JSON responses for the measurement endpoints.
* A plaintext `OK` response for the health endpoint.
