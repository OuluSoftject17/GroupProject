# PR-7

## Purpose

Add a GitHub Actions CI pipeline in `.github/workflows/ci.yml` that runs the
existing tests (`poetry run pytest`) on every pull request to main and every
push to main. It runs two jobs in parallel, one on Windows and one on Linux,
because the harness enforces its limits differently on each.

`python -m harness report` is not run, because shared CI machines give
unreliable timings. No existing code or tests were changed.

### Results 1

The LLM added one file, `.github/workflows/ci.yml` (about 45 lines). It uses
a matrix over `windows-latest` and `ubuntu-latest`, which gives the two
parallel jobs. Beyond the four steps asked for, it added:

* `fail-fast: false`, so a failure on one OS does not cancel the other job
  and both results stay visible.
* `permissions: contents: read`, so the workflow can only read the
  repository.

Poetry is installed with `python -m pip install "poetry>=2,<3"` into the
Python 3.12 set up by `actions/setup-python`. The actions are pinned to
`actions/checkout@v7` and `actions/setup-python@v7`, the latest major
versions at the time.

Checks it ran (Windows 11, Python 3.14):

* `poetry run pytest` gave 16 passed.
* The workflow file parses as valid YAML.

Not checked locally: the Linux job and Python 3.12. They are checked by the
first CI run on the pull request.
