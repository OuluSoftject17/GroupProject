# PR-7

## Purpose

Add a GitHub Actions CI pipeline in `.github/workflows/ci.yml` that runs the
existing tests (`poetry run pytest`) on every pull request to main and every
push to main. It runs two jobs in parallel, one on Windows and one on Linux,
because the harness enforces its limits differently on each.

`python -m harness report` is not run, because shared CI machines give
unreliable timings. No existing code or tests were changed.

### Results 1

The LLM added one file, `.github/workflows/ci.yml` (about 45 lines). It uses
a matrix over `windows-latest` and `ubuntu-latest`, which gives the two
parallel jobs. Beyond the four steps asked for, it added:

* `fail-fast: false`, so a failure on one OS does not cancel the other job
  and both results stay visible.
* `permissions: contents: read`, so the workflow can only read the
  repository.

Poetry is installed with `python -m pip install "poetry>=2,<3"` into the
Python 3.12 set up by `actions/setup-python`. The actions are pinned to
`actions/checkout@v7` and `actions/setup-python@v7`, the latest major
versions at the time.

Checks it ran (Windows 11, Python 3.14):

* `poetry run pytest` gave 16 passed.
* The workflow file parses as valid YAML.

Not checked locally: the Linux job and Python 3.12. They are checked by the
first CI run on the pull request.

### Prompt 2

The first CI run on PR #7 passed on Linux but failed on Windows. Two harness
tests errored with "the device exited before the sensor started", because
the device refused `import posixpath`:

```
File "C:\hostedtoolcache\windows\Python\3.12.10\x64\Lib\mimetypes.py", line 28, in <module>
  import posixpath
ImportError: module 'posixpath' is not installed on the device
```

The LLM found the cause. On Python 3.12, `mimetypes` (imported by
`http.server`) imports `posixpath` when it loads. `posixpath` is not in
`allowed_modules` in `harness/profile.toml`. Locally the tests ran on Python
3.14, where `mimetypes` imports `posixpath` only inside a function. On Linux,
`posixpath` is `os.path` and is already loaded when Python starts, so the
import hook never sees it. Windows with Python 3.12 had never been tested.

The LLM reproduced the failure with a local Python 3.12 and suggested two
places for the fix: this PR, or a separate PR. The group member chose this
PR, quoting the LLM's suggestion:

> lets do
>
> "n this PR (my recommendation): a separate simulator: allow posixpath on Python 3.12 commit, recorded as Prompt 2 in 7.md. The PR then turns green and shows that both the pipeline and the fix work. It does go beyond your original rule of not touching harness/, and reviewers will see a harness change in a CI PR."

### Results 2

The LLM added `"posixpath"` to `allowed_modules` in `harness/profile.toml`,
with a comment explaining why it is needed. No other file under `harness/`
changed. This goes beyond Prompt 1's rule of not touching `harness/`, as
agreed above.

Checks it ran (Windows 11):

* Python 3.12.14 (a separate virtual environment): before the fix, 14 passed
  and 2 errors, the same as CI. After the fix, 16 passed.
* Python 3.14, `poetry run pytest`: 16 passed.
